# yp-explainer-html（読み手が引っかからずに読める HTML 資料）

チャットでは流れて消える説明を、あとから開いて読み返せる HTML ファイル1枚にする。
追加のソフトは要らない。見た目（CSS）と、囲みや年表など写して使える HTML の書き方（以下「部品」）は `assets/template.html` に入っているので、それを写して中身を書く。

## 作り方

1. 資料の目的と読み手を1〜2行で言い直す。読み手の指定がなければ「その話題を初めて知る人」とする
2. 調べて書く内容は、公式の資料や一次資料を先に確かめる。確かめられなかったことは本文に「未確認」と書く
3. `assets/template.html` を保存先へ写し、`{{…}}` を書き換えて本文を書く。`<style>` は書き換えない。その資料だけで要る指定は、`<style>` の末尾に足す
4. 部品（囲み・表・流れ図・年表・カード・画像・折りたたみ）の書き方は、ひな形の末尾のコメントにある。要るものだけを写して使う
5. 仕上げの確認（下の「渡す前に確かめること」）をして渡す

保存先は、依頼者が言わなければ、いま開いているフォルダーにする。同じ名前のファイルがあれば上書きせず、名前の末尾に `_v2` などを付けて別に保存する。

## 書き方

オライリーや結城浩の技術書のように、読み手が引っかからずに読み進められる文章にする。構成は内容に合わせて自由に決める。

- 読み手は前提知識ゼロ。専門用語・固有名（人・場所・制度・ツール・ファイル）は、初めて出たときに「どこの何か」を一言で説明する。難しい読みには読み仮名を添える
- 読み手が抱きそうな「なぜ？」を先に問いとして立て、答え → 理由 → 例の順で書く
- 一般論の前に具体的な場面を見せる。1節では1つのことだけを扱う
- 節の見出しは、話題の名前（「歴史」）でなく、言いたいこと1文（「皇太子の住まいが国の迎賓館になった」）にする。見出しだけを読んで結論の流れが追えるようにする
- 判断や計画の資料は、決めること・やること → それで増える手間や残るもの → なぜその案か → 背景、の順に並べる。判断が3つ以上あれば番号を振る
- 表や図を出す前に、どこを見てほしいかを1文で書く
- 結論・注意・確認してほしい点は囲みに入れて、本文の中から拾えるようにする
- 数値・年・名前は出典のあるものだけを書く。出典は各節の終わりか資料の最後に、1行に1つ、リンクで書く
- 声に出して読み、息をつく所にだけ読点を打つ。短い主語（「この商品は」）の後では区切らず、主語や前置きが長いときだけ打つ
- 1文に読点が3つ以上になったら、文を分ける
- yomiyasu などの日本語を推敲するスキルが入っていれば、仕上げに使う
- 項目を「／」で区切らず、「・」か「や」でつなぐ
- 段落の中では、1文ごとに `<br>` で改行する。続けてよいのは、合わせて40字ほどに収まる短い2文だけ。話題が変わる所は段落を分ける
  - 例: `<p>迎賓館赤坂離宮は明治時代に建てられた宮殿です。<br>今は外国の国王や大統領を迎える場所として使われています。</p>`

## 図

図は入れるのが基本。本文の節ごとに1つ以上を目安にし、図を置かないのは、説明が1段落で済む節か、図にできるものがない節だけにする。
どんな図にするかは内容で決める。形は自由で、次は例にすぎない。

- 場所の話 → 地図（最寄り駅・周りの目印・方角が分かる略図で十分）
- 建物・部屋・機械の話 → 間取り・配置図・断面図
- 年代の話 → 年表
- 手順・仕組み・分岐 → 流れ図
- 案や物の比較 → 表・並べたカード
- 数の比較や推移 → グラフ

描き方も自由に選んでよい。ひな形の部品（流れ図・年表・カード）で済むならそれを使い、形を自由に描きたい図は SVG を本文に直接書く。

- SVG の図は、スマートフォンで画面の幅まで縮んでも、文字が14px以上に見える大きさにする
- 文字が図形からはみ出したり、文字どうしや線と重なったりしないようにする
- 図の下に、図が何を表すかを1文で書く。自分で描いた地図や間取りには、正確な縮尺ではないことも書く

写真や他の人が作った画像を使うときは、権利に気をつける。

- 利用条件で再利用が認められたものだけを使う（パブリックドメイン、クリエイティブ・コモンズなどのライセンス、提供元が利用を認めているもの）。条件を確かめられない画像は使わない
- 画像の下に、出典・作者・ライセンスを書く。ライセンスが求める表示は省かない
- インターネットにつながなくても開けるよう、画像はファイルに埋め込む（`data:` 形式）。表示に要る大きさに縮めてから埋め込む

## 必ず守ること

- インターネットにつながなくても開けるようにする。外部のフォント・CDN・画像の読み込みを使わない
- 書体はひな形の指定（`--font`）を使う。PC に入っている日本語の書体を順に並べてあり、中国語や英語の Windows でも、日本語の書体が入っていれば漢字が日本語の字形で出る。`<html lang="ja">` も消さない
- JavaScript は使わない（頼まれたときだけ足してよい）
- 依頼者の個人情報や、資料に関係のない社内の情報を書かない

## 渡す前に確かめること

できるならブラウザで開いて、次を見る。ブラウザを開けない環境なら、開けなかったことを依頼者に伝える。

- 横にはみ出す表や図がない。ウィンドウを細くしても崩れない
- 図の文字がはみ出したり重なったりしていない
- 図にできるのに、文章や箇条書きだけで済ませた節がない
- 印刷のプレビューで、表・図・囲みがページの途中で切れていない

渡すときは、保存した場所、何を書いたか、確かめたことと確かめていないことを短く伝える。
